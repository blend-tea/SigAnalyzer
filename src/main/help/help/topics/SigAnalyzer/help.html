SigAnalyzer

SigAnalyzer applies IDA FLIRT signatures to existing functions. Open Tools > SigAnalyzer > Open SigAnalyzer to add or remove .sig files for the current program's processor and enable or disable individual signatures.

Run Auto Analyze with SigAnalyzer enabled, or select SigAnalyzer from one-shot analysis. Run the appropriate demangler afterwards when using one-shot analysis.

Signatures must match the program's architecture and ABI. A signature with an unresolved referenced function is skipped until that reference can be verified.

SigAnalyzer runs after Function ID. Functions already identified by Function ID are excluded. Unique FLIRT matches receive a function-entry comment listing their signature files and libraries; existing comments are retained.

FLIRT Conflicts

Different matching names leave the current function name and comment unchanged. The FLIRT Conflicts window opens after analysis and lists each candidate with its address, signature file and library. Double-click a row or press Enter to navigate to its function. Use Tools > SigAnalyzer > FLIRT Conflicts to reopen the latest report. Several signatures agreeing on one name do not create a conflict.

Right-click a candidate and choose Apply FLIRT Candidate to apply an explicit choice after analysis finishes. The name becomes user-defined and retains its FLIRT provenance. Ghidra Undo/Redo is supported. Function ID results, imported names and entry points remain protected.

Signature Groups and YARA

In the signature manager, select or create a directory group and add or move signatures into it. Existing signatures remain in the default group.

Use Edit rule or Import rule to add an optional rules.yar. At least one YARA rule must match the original imported binary before the signatures directly in that folder are analyzed. Child folders do not inherit rules. Remove the rule to analyze that group without a YARA condition.

Install native YARA 4 or configure its full executable path in the SigAnalyzer analysis options. The scan timeout defaults to 30 seconds per group. Rule errors, missing YARA or missing original bytes skip only the affected group and are reported in the analysis log. Groups without rules do not require YARA.
